C-01

Product contract

These rules resolve design decisions. They describe behavior, not merely appearance, and apply to every current and future tracker.

1 Data integrity

Record the intended event and wall time; never fabricate detail.

→
2 User agency

Make capture reversible, editable, and understandable.

→
3 Low effort

Minimize decisions and actions in the frequent path.

→
4 Useful reflection

Turn records into context without claiming causation.

MUST

A release-blocking requirement for correctness, accessibility, or trust.

SHOULD

The default pattern. Deviations need a written product reason.

MAY

An optional enhancement that cannot become the only usable path.

Do Design the whole record lifecycle

Specify entry, confirmation, sync, correction, review, and deletion together.

Avoid Optimizing only the logging screen

A fast event that cannot be verified or corrected creates invisible data debt.

C-03

Tracking lifecycle

Tracking is an ongoing loop, not a streak. A feature is incomplete if it supports collection but not interpretation, action, and resumption.

  1. Prepare Choose what matters

    Intent, fields, cadence, and privacy are clear before logging.

  2. Capture Record with low effort

    Fast defaults, honest detail, immediate confirmation.

  3. Integrate Make records coherent

    Normalize time, pair intervals, sync, and expose data quality.

  4. Reflect Answer a question

    Use context, comparison, and accessible underlying values.

  5. Act Choose a next step

    Offer an optional adjustment, not a moral verdict.

↻
Lapse → resume is a first-class path

Missing days MUST NOT trigger shame, forced backfill, broken-state visuals, or permanent loss of progress. Return users see a neutral present-tense action: “Log now.”

Reminder contract

User controlled Opt in and adjustable

Cadence, quiet hours, snooze, pause, and disable remain easy to change.

Contextual Prompt near the useful moment

A reminder supports capture; it does not punish an unlogged interval.

Private Generic by default

Lock-screen copy hides sensitive tracker names and values unless explicitly enabled.

Time is domain data.

Every RFC MUST define whether a record is an instant, interval, duration, or wall-date fact; what its timestamp means; how it behaves across midnight; and how an IANA timezone resolves edits. Follow the date and time input contract and use tested domain helpers—never local ad hoc date math.

I-01

Navigation and growth

Navigation represents stable destinations, never logging actions. Labels, order, and meaning stay consistent across mobile and desktop.

1Today 2Sleep 3Nutrition 4Gym 5Mind

Canonical current destinations: Today / Sleep / Nutrition / Gym / Mind. “Floor” and “Food” are not alternate navigation labels.

1–5 destinations Expose all five

Keep a stable order on every surface. Current active destination remains visible.

6+ destinations Introduce domains

Group related trackers into a hub or intentional “More” destination; do not keep appending tabs.

Frequent capture Use capture surfaces

Place actions on Today or inside the relevant domain—not in the tab bar.

Rule Contract
Names Use one canonical user-facing label across tab bar, rail, page title, and links.
Order Repeated navigation MUST keep the same relative order.
Icons Support recognition; never replace a required text label on mobile.
Deep links Every review or history view has a stable URL and clear way back to its domain.
I-02

Capture contract

The fastest path is determined by data certainty. Speed never justifies saving an invented or ambiguous record.

Can safe defaults produce a truthful record?
→
Yes Primary activation logs now

Confirm immediately; expose Undo and Edit.

No Primary activation opens composer

Focus the first meaningful missing field.

Input Required behavior Never rely on
Tap / click Execute the named primary action consistently. Hidden gesture knowledge
Keyboard Enter/Space matches primary activation; shortcuts are supplemental. A shortcut as the only path
Long press MAY accelerate an action only when a visible alternative exists. Long press for essential detail
Drag Provide buttons, fields, or other single-pointer no-drag alternative. Drag-only time correction
Voice / assistive tech Accessible name states event and outcome: “Log coffee now”. Icon shape or color alone

After capture

  1. 0–150 msPressed or progress feedback
  2. ImmediateOptimistic record with visible pending state
  3. Up to 12 sUndo remains available without blocking continued use
  4. On syncPending state resolves without moving the record unexpectedly
  5. On failureKeep the record, explain status, and offer Retry/Edit
Current conformance note

Desktop currently uses click to open and hold to log, while mobile presents other behavior. This inversion is legacy debt. Future trackers MUST follow the contract above; do not copy the inversion.

I-03

Forms and overlays

Sheets and dialogs collect only what is needed for a trustworthy record. They behave as one semantic form across breakpoints.

  1. 1 · Identity Action-specific title and visible close button.
  2. 2 · Minimum fields Required before optional; labels remain visible.
  3. 3 · Commit Explicit outcome label; never generic “OK”.

Dialog keyboard contract

  • Focus moves inside when opened.
  • Tab and Shift+Tab stay inside.
  • Escape closes when doing so is safe.
  • Focus returns to the control that opened it.
  • Role, title, and description are programmatically associated.

Validation contract

  • Validate on submit; use earlier validation only when it helps.
  • Preserve every value after an error.
  • Say what happened and how to fix it.
  • Put the message next to the field and summarize when multiple fail.
  • Move focus to the error summary when one is present.
I-04

Date and time inputs

Date and time are part of the record’s meaning. The shared input must be typable, backdateable within policy, timezone-safe, and stable inside a mobile sheet before it is visually distinctive.

→

ContractRequired behavior
Direct entry Date and time are visible editable fields on desktop. The React Aria target enforces 24-hour segments; native fallback values serialize as HH:mm but may display in the device locale. A calendar is an additional path, never the only path.
Date choice Now, Today, and Yesterday are shortcuts. “Choose date” exposes every date permitted by the tracker’s range.
Mobile overlay The form body owns vertical scrolling. Swipe-to-dismiss can begin only on the handle or header, never on a field or calendar.
Now Store a live-now intent and resolve it when Save is pressed; do not freeze the time when the sheet opens.
Bounds Past-only by default. UI and API share min/max rules; future values require an explicit planned-event product state.
Precision Exact, About, and Part of day are different domain values. Approximate entries never become invented exact minutes.
Timezone Resolve wall time in an explicit IANA zone and show the zone in the editor. Never preserve a stale offset across an edit.
Validation Never silently clamp invalid input. Preserve it, explain the correction, associate the error, and focus the invalid field.

Responsive contract

Mobile sheet

  • Use the platform picker or an equally tested touch control.
  • Keep Close/Cancel and the outcome action visible.
  • Contain body overscroll and respect keyboard/safe-area insets.
  • Do not put a vertically scrolling wheel inside a draggable sheet.
  • Protect a changed draft from accidental dismissal.

Desktop popover

  • Typing works immediately; the picker button is supplemental.
  • Enter applies only a complete valid value.
  • Escape cancels and returns focus to the invoker.
  • The closed field summarizes date, time, zone, and approximation.
  • Intervals use a dialog when a small popover cannot remain clear.

I-06

System states

A tracker must specify state behavior before implementation. Silence is not an acceptable loading, offline, or failure state.

Localcreated Queuedoffline Syncingin flight Syncedconfirmed Failedretryable
View state What is shown Available action
First load Structure-matched skeleton or compact progress status. None unless load becomes slow.
Empty Plain reason plus what will appear here. One relevant capture action.
Offline Existing data stays usable; queued records are labeled. Continue logging; optional Retry.
Partial data Known values plus precise missing-data note. Add or edit missing detail.

Status is semantic.

Async confirmations and failures MUST be announced through an appropriate live status region without unexpectedly moving focus. Color and animation may reinforce the message, never carry it alone.

U-01

Reflection and charts

Start with the user’s question, then choose the smallest representation that answers it. A chart without a decision or reflection task is noise.

Status mode Glance, orient, continue

Current value, data coverage, chosen-range comparison, and at most one relevant action.

Explore mode Investigate, compare, annotate

History, filters, source records, goals, context, anomalies, and cross-domain overlays.

When?Timeline

Sequence, gaps, and daily rhythm.

How much?Value + trend

Magnitude with recent context.

How often?Calendar or bars

Frequency by day or week.

What changed?Before / after

Comparable periods and explicit baseline.

What relates?Paired context

Aligned observations with no causal claim.

Chart release contract

Say “Energy was higher on 4 of 5 logged gym days.”

Names the data, denominator, and scope.

Avoid “Gym improves your energy.”

Implies causation and hides missing or confounding context.

U-02

Goals, tone, and nonjudgment

Personal data can inform without grading the person. Goals are optional, user-selected, revisable, and separate from the factual record.

Observation “6 h 42 min sleep”

Always available. Neutral and factual.

User goal “Target: 7–8 hours”

Shown only when the user set or accepted it.

Reflection “45 min below your range”

Context, not success/failure identity.

Next action “Adjust tonight’s reminder”

Optional and directly controllable.

Prefer Avoid Reason
No data logged Failed day Absence is not a moral outcome.
Outside your range Bad / unhealthy Names user context without diagnosing.
Resume logging Restore your streak Supports return without loss framing.
Pattern to explore We found the cause Observational data rarely establishes causality.
U-03

Cross-tracker relationships

A larger Tracker becomes valuable when domains can be viewed together, but combination must preserve provenance, uncertainty, and user control.

Sleep Caffeine Energy
→
Question “How did next-morning energy vary with bedtime and late caffeine?”

Align by explicit windows; show the individual records behind the summary.

Combination requirements

  • Define join key and time window.
  • Show sample size and missing records.
  • Let users inspect contributing events.
  • Use “associated with” or factual comparison language.
  • Allow tracker inclusion to be changed.

Do not combine when

  • Timestamps have incompatible meanings.
  • Sample size cannot support the proposed summary.
  • Missingness is likely to distort the view.
  • The result would reveal sensitive data out of context.
  • The product cannot explain the calculation.

Q-03

Privacy and trust

Life-tracking data is sensitive even when a field looks ordinary. Collection, display, and sharing use the minimum necessary information.

Collect

Only fields needed for the stated tracker purpose.

Explain

Plain-language reason at the point of request.

Control

Edit, archive, restore, export, and inclusion choices.

Protect

Lock sensitive surfaces and avoid accidental exposure.

Do Ask in context

Explain why a sensitive field or permission is useful immediately before it is needed.

Avoid Future-proof collection

Do not collect extra life data only because a future feature might use it.

PIN and accessible authentication

Input contract

  • Use one semantic PIN input even if it looks segmented.
  • Allow paste, autofill, and password-manager assistance.
  • Provide a visible label, numeric keyboard hint, and Show/Hide control.
  • Preserve the value after failure, announce the error, and focus the field.

Alternative contract

  • Keep a non-memory option such as passkey visible when feasible.
  • Do not make manual transcription or a cognitive puzzle the only path.
  • Rate-limit abuse without introducing inaccessible CAPTCHA.
  • Explain session expiry before requiring unlock again where possible.
Q-04

Content system

Copy describes an observable state and the next available action. It is compact, human, specific, and stable across surfaces.

Element Pattern Example
Capture action Verb + object + time when relevant Log coffee now
Dialog title Verb + record Edit sleep
Confirmation Past-tense outcome + key detail Coffee logged at 14:20
Error Problem + retained state + recovery Couldn’t sync this meal. It is saved on this device. Retry.
Empty state What is absent + how it appears No gym sessions this week. Log one when you finish.

Vocabulary rules

  • Today is the cross-domain activity view.
  • Nutrition is the canonical food domain label.
  • Record is a saved item; event is the technical model.
  • Log creates; Edit corrects; Undo reverses a recent action.

Error language rules

  • No “Oops”, blame, or vague “Something went wrong”.
  • Do not expose Notion or transport implementation terms.
  • Say whether the record is safe, queued, or needs attention.
  • Use the same event name as the originating surface.

Q-06

Governance and conformance

The design system stays useful only when decisions, code, and examples evolve together. Known divergence is recorded, prioritized, and never copied forward.

Change behavior Update contract → code → specimen

Include the reason and migration impact in the feature review.

Change tokens Update app → mirror → check

The app token file is authoritative; the checker prevents drift.

Find divergence Record debt → set target

Document current behavior and the intended contract separately.
